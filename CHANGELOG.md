# Changelog

## 18.0.0 — Unicode 18.0 support

Upgrades the Unicode Character Database from Unicode 17.0 to Unicode 18.0 (including Unihan and emoji data).

### ⚠️ Breaking changes

- **Algorithmic character names have changed.** Names of characters in ranges of `UnicodeData.txt` are now the standard ones from `DerivedName.txt`. Previously the range label was simply upper-cased, which gave non-standard names.
  - CJK ideographs (basic block and Extensions A–J): `CJK IDEOGRAPH EXTENSION B-29C0A` → `CJK UNIFIED IDEOGRAPH-29C0A` (and `CJK IDEOGRAPH-4E00` → `CJK UNIFIED IDEOGRAPH-4E00`).
  - Surrogates and private use characters (including planes 15 and 16) now have a `null` name instead of names such as `PRIVATE USE-E000`.
  - Tangut, Tangut Supplement and Hangul syllable names are unchanged.
  - New in 18.0: `SMALL SEAL CHARACTER-xxxxx` and `JURCHEN CHARACTER-xxxxx`.
- **`UnicodeCharInfo.SimplifiedVariant` and `UnicodeCharInfo.TraditionalVariant` now return all values.** Previously only the first value was returned. When a character has several variants they are concatenated in one string, e.g. the traditional variants of U+4E07 are now `"万萬"` instead of `"万"` (about 550 characters are affected). Code that assumed a single character must handle longer strings.
- **Negative radical/stroke counts are no longer clamped to -4.** `UnicodeRadicalStrokeCount.StrokeCount` supports values from -16 to 111 (was -4 to 123), so U+29C0A, U+29C0B (191.-5) and U+33473 (212.-9) now report their real values. Values above 111 would now be clamped (none exist in Unicode 18; the maximum is 76).
- **Removed public constants from `System.Unicode.Build.Core.UnihanProperty`** (and `UnihanProperty.tt`). These properties no longer exist in Unicode 18, or had already been removed from the Unihan database and were never used:
  - Removed in Unicode 18: `IRGDaeJaweon` (`kIRGDaeJaweon`), `IRGKangXi` (`kIRGKangXi`).
  - Already obsolete: `Frequency`, `GB7`, `HKSCS`, `IRGDaiKanwaZiten`, `KPS0`, `KPS1`, `KSC0`, `KSC1`, `RSJapanese`, `RSKangXi`, `RSKanWa`, `RSKorean`.
- **`ucd.dat` binary layout changed.** Two new Unihan fields were added, so the database must be regenerated with the matching builder. Databases generated by older versions of the builder cannot be read by this version (and vice versa).

### Added

- Unicode 18.0 data (`UnicodeVersion.txt`, regenerated `ucd.dat`).
- New Unihan properties on `UnicodeCharInfo`:
  - `JapaneseOldVariant` (`kJapaneseOldVariant`)
  - `JapaneseNewVariant` (`kJapaneseNewVariant`)

  Multiple values are concatenated in a single string.
- New blocks from Unicode 18 (read from `Blocks.txt`): Bengali Supplement, Archaic Cuneiform Numerals, Jurchen, Jurchen Radicals, Musical Symbols Supplement, Miscellaneous Symbols and Arrows Extended, Seal.
- The database builder now fails with an explicit error on an unknown range label in `UnicodeData.txt`, instead of silently producing wrong names.
- New tests: Japanese variants, multi-valued simplified/traditional variants, preserved negative stroke counts, algorithmic names.

### Fixed

- Version detection in the database builder supports the Unicode 18 `ReadMe.txt` wording ("version 18.0.0 of the Unicode Character Database").
- Existing tests that expected the old, non-standard CJK extension names have been updated.

### Changed

- README and package release notes updated to Unicode 18.0.
- README lists the new supported Unihan properties.
